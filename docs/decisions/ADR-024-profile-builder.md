# ADR-024: Owner profile builder and owner-named risk profiles

- **Status:** accepted · **Date:** 2026-11-03 · **Owner request:** "ask each individual risk
  profile questions, then build their trading specs" (chosen: just the owner, per profile;
  terminal and web; every risk value with options).

## Decision

1. `trader profile build` interviews the owner one question per setting and writes
   `configs/risk/<name>.yaml`, `configs/profiles/<name>.yaml`, and `docs/profiles/<name>-spec.md`.
   `trader profile build --answers answers.json` builds from the web form
   (`docs/profile-builder/index.html`, generated by `scripts/build_profile_form.py` from
   `trader profile questions`).
2. **Options come only from the spec.** Each risk question offers the starting preset's column
   of the UD-01..UD-17 option tables. A custom value is accepted only inside the envelope of
   those options across all three presets (for example the breaker 8–30%, risk per trade
   0.25–2%). Safety thresholds (errors, stale data, clock skew) accept only the spec options.
   Nothing is defaulted silently: the owner answers or explicitly accepts each value, and each
   is written `status: approved` with the owner's name and date.
3. **Named risk profiles.** `risk_profile_id` may be any lowercase name (`^[a-z][a-z0-9-]{2,63}$`)
   instead of only the three presets. The presets and `balanced-paper` are reserved names.
   The compiler now also checks that `configs/risk/<id>.yaml` declares the same ID (PV-04).
4. **PV-03 generalized.** Every owner-built risk profile sets
   `selection.explicit_selection_required: true`, and the compiler requires the owner's
   written acknowledgement for any such profile, as D-06 already did for Aggressive.
5. **Compile before write.** The builder compiles the result for backtest and paper in a
   scratch copy of `configs/` with a scratch operational store, and writes nothing if there
   is any error (for example exposure + reserve floor > 100%, RP-01).
6. **Session defaults.** The trading profile records `trading_spec` (strategy and decision
   timeframe). `trader session run` uses it when `--strategy`/`--timeframe` are not given.

## Unchanged

Live gates (ADR-023), the capital cap, the adapter allowlist, activation records, and the
paper-cycle prerequisite apply to built profiles exactly as before. Built profiles are spot
only: the template's leverage, margin, shorting, withdrawal, and transfer constants are
copied unchanged and cannot be answered. The intraday slice stays disabled
(`intraday_strategies_enabled: false`) until it is built, whatever cap the owner records.
